# 图（Graph）原理：邻接表 vs 邻接矩阵

> 本文档讲清「图是什么、两种表示（邻接表 vs 邻接矩阵）在空间/查找/遍历上的差异、稀疏图为什么必须用邻接表、C 实现逐行讲解、复杂度」。AI 应用（PageRank + GNN 消息传递）见 `ai_application.md`。

## 1. 图的定义：关系的数据结构

**图**（Graph）是表达**实体间关系**的最通用的数据结构。一个图 $G = (V, E)$ 由两部分组成：

- **顶点集** $V$（vertices）：n 个实体，如网页、用户、神经元
- **边集** $E$（edges）：实体间的关系，每条边连接一对顶点 $(u, v)$

```
无向图（朋友关系）:          有向图（网页链接）:

    0 --- 1                    0 → 1
    | \ /                      ↓   ↓
    |  2                       2 ← 3
    | /                        ↑
    3                          4 → 2

  V = {0,1,2,3,4}             V = {0,1,2,3,4}
  E = {01,02,12,13,23,24}     E = {0→1, 0→2, 1→3, 3→2, 4→2}
```

图能表达的关系远比线性表、树丰富：树是「每个节点一个父节点」的特殊图，线性表是「每个节点最多一个后继」的更特殊图。社交网络、网页链接、知识图谱、分子结构、神经网络拓扑——都是图。

### 1.1 两个核心维度：有向性 + 稀疏性

| 属性 | 取值 | 影响 |
|---|---|---|
| 有向性 | 有向 / 无向 | 无向边 $(u,v)$ 和 $(v,u)$ 是同一条；有向边有方向 |
| 稀疏性 | 稀疏 / 稠密 | 由边数 $\|E\|$ 相对 $\|V\|^2$ 的比例决定 |

**稀疏图**：$|E| \ll |V|^2$，即大部分顶点对之间没有边。现实中的图几乎都是稀疏的：

- 网页图：千亿网页，但每个页面平均只有几十个出链
- 社交网络：十亿用户，但每人平均几百个好友（远小于十亿）
- 知识图谱：百万实体，每个实体平均几十条关系

**稠密图**：$|E| \approx |V|^2$，大部分顶点对都有边。现实中少见，典型是完全图（所有顶点互连）。

稀疏性直接决定**用哪种表示**——这正是本文的核心。

## 2. 两种表示：邻接表 vs 邻接矩阵

给定图 $G = (V, E)$，$|V| = n$，两种存储方式：

### 2.1 邻接表（Adjacency List）

每个顶点维护一个**链表/动态数组**，存它的所有邻居。

```
图:  0---1
     | \|
     2---3

邻接表:
  0 → [1, 2, 3]
  1 → [0, 3]
  2 → [0, 3]
  3 → [0, 1, 2]
```

空间：$O(|V| + |E|)$。每条边在无向图里存两次（$u$ 的表里有 $v$，$v$ 的表里有 $u$），有向图存一次。

### 2.2 邻接矩阵（Adjacency Matrix）

$n \times n$ 的二维数组 $A$，$A[u][v] = 1$ 表示有边 $(u,v)$，$0$ 表示无边。

```
图:  0---1
     | \|
     2---3

邻接矩阵:
       0  1  2  3
    0 [ 0  1  1  1 ]
    1 [ 1  0  0  1 ]
    2 [ 1  0  0  1 ]
    3 [ 1  1  1  0 ]
```

空间：$O(|V|^2)$，不管有没有边都要存。无向图的矩阵是对称的。

### 2.3 三维对比：空间 / 查找 / 遍历

| 操作 | 邻接表 | 邻接矩阵 | 说明 |
|---|---|---|---|
| **空间** | $O(\|V\|+\|E\|)$ | $O(\|V\|^2)$ | 稀疏图 $\|E\| \ll \|V\|^2$，邻接表省巨量空间 |
| **查边 $(u,v)$ 是否存在** | $O(\deg(u))$ | $O(1)$ | 邻接矩阵直接下标；邻接表要扫 $u$ 的邻居链表 |
| **遍历 $u$ 的所有邻居** | $O(\deg(u))$ | $O(\|V\|)$ | 邻接表只碰实际邻居；矩阵要扫整行（含 0） |
| **加边** | $O(1)$ | $O(1)$ | 都快，邻接表 push 到链表尾，矩阵置 1 |
| **遍历所有边** | $O(\|V\|+\|E\|)$ | $O(\|V\|^2)$ | 邻接表只碰真实边；矩阵扫所有 $n^2$ 格 |

关键洞察：

1. **邻接矩阵查边快** $O(1)$，但代价是 $O(V^2)$ 空间
2. **邻接表遍历邻居快** $O(\deg(u))$，只碰实际存在的边——这是 PageRank、GNN 等图算法的核心操作
3. **稀疏图下邻接表空间完胜**：$|E| = O(V)$ 时，邻接表 $O(V)$，矩阵 $O(V^2)$，差 $V$ 倍

### 2.4 一个具体数字

n=1000 顶点，边数=5000（平均度 10，密度 0.01）：

| 表示 | 内存 | 遍历所有边 |
|---|---|---|
| 邻接表 | ~286 KB | 5000 条边 |
| 邻接矩阵 | ~7812 KB | 100 万格（99% 是 0） |
| CSR 稀疏矩阵 | ~121 KB | 5000 条边 |

邻接矩阵用了 **27 倍**内存，遍历时还要扫 100 万格里的 99 万个 0。这就是稀疏图必须用邻接表的根本原因。

## 3. 稀疏图 vs 稠密图：怎么选

### 3.1 选择准则

```
边数 |E| 相对 |V|²:
  |E| << |V|²  → 稀疏 → 邻接表（省空间，遍历只碰真实边）
  |E| ≈ |V|²   → 稠密 → 邻接矩阵（查边 O(1)，空间不浪费）
```

具体阈值：当 $|E| > |V|^2 / \text{指针大小}$ 时，邻接表的空间优势消失（每条边的指针开销赶上矩阵的一个格）。64 位系统下大约 $|E| > |V|^2 / 8$ 时考虑用矩阵。

### 3.2 现实中的图几乎都是稀疏的

| 图 | $\|V\|$ | 平均度 $\|E\|/\|V\|$ | 密度 $\|E\|/\|V\|^2$ | 稀疏? |
|---|---|---|---|---|
| 网页链接 | ~$10^{11}$ | ~30 | ~$10^{-10}$ | 极稀疏 |
| Twitter | ~$3 \times 10^8$ | ~100 | ~$10^{-7}$ | 极稀疏 |
| 蛋白质相互作用 | ~$10^4$ | ~5 | ~$10^{-4}$ | 稀疏 |
| 完全图 $K_n$ | $n$ | $n-1$ | ~1 | 稠密 |

所以**图算法的默认选择是邻接表**。邻接矩阵只在稠密图或需要频繁 $O(1)$ 查边时用。

### 3.3 CSR：邻接表的紧凑数组存储

生产级图库（GraphBLAS、GNN 框架）用 **CSR（Compressed Sparse Row）** 格式，本质是邻接表的数组化：

```
邻接表:                   CSR:
  0 → [1, 2, 3]           data    = [1, 2, 3, 0, 3, 0, 3, 0, 1, 2]
  1 → [0, 3]              indices = [1, 2, 3, 0, 3, 0, 3, 0, 1, 2]
  2 → [0, 3]              indptr  = [0, 3, 5, 7, 10]
  3 → [0, 1, 2]
                           顶点 u 的邻居 = indices[indptr[u]:indptr[u+1]]
```

三个数组：
- `data`：所有边的目标顶点，连续存储
- `indices`：邻居顶点编号
- `indptr`：每行起始位置，长度 $|V|+1$

CSR 的优势：

1. **空间最优**：没有链表指针开销，纯数组，$O(|V|+|E|)$ 且常数小
2. **缓存友好**：连续内存，CPU 缓存命中率高
3. **C/Fortran 层运算**：scipy.sparse、PyG、DGL 都用 CSR 接 BLAS 级稀疏运算

本 demo 的 CSR 版（scipy.sparse）在 PageRank 上比 dense 矩阵快 16x，比纯 Python 邻接表快 58x——既省内存又快。

## 4. C 实现逐行讲解

本实现用邻接表，文件 `09_graph/c/graph.h` + `graph.c`。

### 4.1 数据结构（graph.h）

```c
typedef struct {
    int *data;
    size_t size;
    size_t capacity;
} AdjList;

typedef struct {
    size_t n_vertices;
    AdjList *adj;
    int directed;
} Graph;
```

- `AdjList`：动态数组存邻居顶点号。`data` 是 int 数组，`size` 当前长度，`capacity` 容量
- `Graph`：`n_vertices` 个 `AdjList`，每个顶点一个。`directed` 标记有向/无向

用动态数组而非链表存邻居，原因：缓存友好、随机访问 $O(1)$、无指针开销。这是现代图库的标配做法。

### 4.2 初始化和释放（graph.c）

```c
void graph_init(Graph *g, size_t n_vertices, int directed) {
    g->n_vertices = n_vertices;
    g->directed = directed;
    g->adj = (AdjList *)calloc(n_vertices, sizeof(AdjList));
}

void graph_free(Graph *g) {
    for (size_t i = 0; i < g->n_vertices; i++) {
        free(g->adj[i].data);
    }
    free(g->adj);
    g->adj = NULL;
    g->n_vertices = 0;
}
```

`calloc` 把每个 `AdjList` 的 `data/size/capacity` 都清零，初始状态所有顶点度数为 0。释放时先释放每个顶点的邻居数组，再释放顶点数组本身。

### 4.3 加边（graph_add_edge）

```c
static void adj_push(AdjList *a, int v) {
    if (a->size == a->capacity) {
        size_t new_cap = a->capacity == 0 ? 4 : a->capacity * 2;
        int *new_data = (int *)realloc(a->data, new_cap * sizeof(int));
        a->data = new_data;
        a->capacity = new_cap;
    }
    a->data[a->size++] = v;
}

void graph_add_edge(Graph *g, int u, int v) {
    adj_push(&g->adj[u], v);
    if (!g->directed) {
        adj_push(&g->adj[v], u);
    }
}
```

`adj_push` 是动态数组的倍增扩容：满了就 `realloc` 两倍容量。初始容量 4，扩容策略保证均摊 $O(1)$ 加边。

`graph_add_edge`：无向图加两条（$u \to v$ 和 $v \to u$），有向图只加一条。这是两种图的唯一区别。

### 4.4 查边和遍历

```c
int graph_has_edge(const Graph *g, int u, int v) {
    return adj_contains(&g->adj[u], v);  // 扫 u 的邻居链表
}

const int *graph_neighbors(const Graph *g, int u, size_t *out_count) {
    *out_count = g->adj[u].size;
    return g->adj[u].data;  // 返回邻居数组指针 + 长度
}

size_t graph_degree(const Graph *g, int u) {
    return g->adj[u].size;  // O(1)
}
```

- `has_edge`：$O(\deg(u))$ 线性扫邻居。如果频繁查边，可对每个邻居数组排序后二分 $O(\log \deg)$，或换哈希表 $O(1)$
- `neighbors`：返回邻居数组指针和长度，调用方直接遍历连续内存，缓存友好
- `degree`：$O(1)$，动态数组的 `size` 就是度数

### 4.5 测试（test.c）

测试覆盖：

- `test_init_free`：初始化 + 释放，验证初始度数全 0
- `test_add_edge_undirected`：无向图加边，验证双向都有
- `test_add_edge_directed`：有向图加边，验证单向
- `test_has_edge_nonexistent`：查不存在的边返回 0
- `test_neighbors_traversal`：遍历邻居，验证邻居集合正确
- `test_self_loop` / `test_self_loop_undirected`：自环
- `test_complete_graph`：5 顶点完全图，每顶点度数 4
- `test_handshake_lemma`：握手定理 $\sum \deg = 2|E|$，无向图核心不变量
- `test_directed_handshake`：有向图 $\sum \deg_{\text{out}} = |E|$
- `test_path_traversal`：沿有向路径 0→1→2→3→4→5 走一遍
- `test_star_graph`：星形图，中心度数 5，叶子度数 1

**握手定理**（handshake lemma）是图最基本的不变量：无向图所有顶点度数之和等于边数的两倍。测试用随机图验证这个恒等式，是检查加边实现正确性的强约束。

## 5. 复杂度

| 操作 | 邻接表 | 邻接矩阵 |
|---|---|---|
| 空间 | $O(\|V\|+\|E\|)$ | $O(\|V\|^2)$ |
| 加边 | $O(1)$ | $O(1)$ |
| 删边 | $O(\deg(u))$ | $O(1)$ |
| 查边 $(u,v)$ | $O(\deg(u))$ | $O(1)$ |
| 顶点 $u$ 的度 | $O(1)$ | $O(\|V\|)$（数 1）或 $O(1)$（维护） |
| 遍历 $u$ 的邻居 | $O(\deg(u))$ | $O(\|V\|)$ |
| 遍历所有边 | $O(\|V\|+\|E\|)$ | $O(\|V\|^2)$ |
| BFS / DFS | $O(\|V\|+\|E\|)$ | $O(\|V\|^2)$ |

**图算法的复杂度几乎都含 $|V|+|E|$ 项**（BFS、DFS、PageRank、GNN 消息传递都是）。邻接表让这些算法达到理论最优 $O(|V|+|E|)$；邻接矩阵让它们退化到 $O(|V|^2)$，稀疏图上白白扫大量 0。

## 6. 邻接表 vs 邻接矩阵：什么时候用哪个

| 场景 | 选谁 | 原因 |
|---|---|---|
| **稀疏图 + 遍历为主**（PageRank、GNN、BFS） | 邻接表 | $O(\|V\|+\|E\|)$ 只碰真实边 |
| **稠密图**（$\|E\| \approx \|V\|^2$） | 邻接矩阵 | 空间不浪费，查边 $O(1)$ |
| **频繁查边**（$(u,v)$ 是否存在） | 邻接矩阵 | $O(1)$ vs $O(\deg)$ |
| **频繁加删边** | 邻接表（链表） | 矩阵删边 $O(1)$ 但空间固定 $O(V^2)$ |
| **超大图**（内存受限） | 邻接表 / CSR | $O(\|V\|+\|E\|)$ 空间 |
| **需要矩阵运算**（谱聚类、矩阵幂） | 邻接矩阵 | 直接用 BLAS |

**AI 场景的默认选择**：图神经网络、PageRank、随机游走——全是稀疏图 + 遍历为主，一律邻接表（或 CSR）。这也是 PyG、DGL 等框架底层的做法。

## 7. 从邻接表到 CSR：生产级的进化

教学版的邻接表（每顶点一个动态数组/链表）有指针开销、缓存不友好。生产级图库用 **CSR** 把邻接表压成三个连续数组：

```
邻接表（教学版）:              CSR（生产版）:
  0 → [1,2,3]  (链表/动态数组)   data   = [1,2,3,0,3,0,3,0,1,2]
  1 → [0,3]                     indptr  = [0, 3, 5, 7, 10]
  2 → [0,3]                     
  3 → [0,1,2]                   顶点 u 的邻居 = data[indptr[u]:indptr[u+1]]
```

CSR 的本质：把邻接表的「每顶点一个独立数组」拍平成「一个大数组 + 偏移表」。好处：

1. **无指针开销**：纯数组，每条边只存一个 int（4 字节），邻接表的动态数组有 header + capacity 浪费
2. **缓存友好**：遍历某顶点邻居是连续内存读取，CPU 缓存行命中率高
3. **接 BLAS**：CSR 是稀疏矩阵的标准格式，scipy.sparse、PyG、DGL 都用 CSR 接 C/Fortran 层稀疏运算

本 demo 实测（n=1000, 边=5000）：

| 表示 | 内存 | PageRank 50 轮 | GNN 消息传递 |
|---|---|---|---|
| 邻接表（dict + ndarray） | 286 KB | 93 ms | 5.8 ms |
| 邻接矩阵（dense） | 7812 KB | 23 ms | 1.15 ms |
| CSR（scipy.sparse） | 121 KB | 1.6 ms | 0.19 ms |

CSR 内存最小（121 KB）、速度最快（PageRank 1.6ms，GNN 0.19ms）。纯 Python 邻接表虽然逻辑 $O(|V|+|E|)$，但 Python 循环常数太大；dense 矩阵靠 BLAS 向量化快但 $O(V^2)$ 内存；CSR 兼顾两者优势——$O(|V|+|E|)$ 空间 + C 层运算速度。

**结论**：邻接表是稀疏图正确的数据结构，CSR 是它的生产级形态。下一章的 AI 应用会看到 PageRank 和 GNN 都建立在「沿边聚合」上，邻接表/CSR 让聚合只碰真实存在的边。
