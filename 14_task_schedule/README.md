# 第 14 章 · 任务调度与批处理（扩展专题）

> AI 场景：LLM 推理服务的任务调度、动态批处理、负载均衡

## 本章要回答的问题

- 请求有优先级，谁先处理？（堆）
- 推理流水线有依赖，按什么顺序执行？（DAG + 拓扑排序）
- 请求要凑批提高吞吐量，怎么收集？（队列 + 动态批处理）
- 多节点负载均衡，节点增减怎么少迁移？（一致性哈希）
- 4 种数据结构如何协奏？

## demo 概览

模拟 LLM 推理服务，4 种数据结构协作：

```
请求到达 → [堆]优先级排序 → [DAG]依赖检查 → [队列]凑批 → [一致性哈希]分发到节点
```

- `PriorityHeap`：堆，请求优先级调度（VIP/SLA 优先）
- `DependencyDAG`：DAG + 拓扑排序，推理流水线依赖
- `DynamicBatcher`：队列，动态批处理（凑批或超时发批）
- `ConsistentHashing`：一致性哈希，多节点负载均衡（虚拟节点 + 环形空间）

性能对比：
1. 优先级调度 vs FIFO（VIP 延迟 19.9x 差异）
2. 动态批处理 vs 单请求（吞吐量 3.33x 提升）
3. 一致性哈希 vs 取模哈希（节点增减迁移量 4.0x 差异）
