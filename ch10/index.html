    原理¶

    并查集（Disjoint Set）原理：父指针 + 路径压缩 + 按秩合并¶

    本文档讲清「并查集是什么、父指针表示、find 和路径压缩、union 和按秩合并、为什么近 O(1)（Ackermann 反函数 α(n)）、C 实现逐行讲解、与 BFS/DFS 判连通对比」。AI 应用（层次聚类 HAC）见 ai_application.md。

    1. 并查集是什么：维护"属于同一集合"的数据结构¶

    并查集（Disjoint Set Union, DSU）是维护若干不相交集合的数据结构，支持两个核心操作：

    • find(x)：返回元素 x 所在集合的代表元（根）
    • union(x, y)：把 x 和 y 所在的两个集合合并成一个

    并查集不关心集合里有什么元素，只关心哪些元素属于同一集合。这是很多算法的核心需求：

    • 连通分量：图中两个顶点是否连通？合并就是加边
    • Kruskal 最小生成树：加边时判断两端是否已连通（避免成环）
    • 等价类：哪些变量相等？合并就是加等式约束
    • 层次聚类：哪些点属于同一簇？合并就是两个簇合体
    初始: {0}, {1}, {2}, {3}, {4}     每个元素自成一集

union(0, 1): {0,1}, {2}, {3}, {4}
union(2, 3): {0,1}, {2,3}, {4}
union(0, 2): {0,1,2,3}, {4}       0 和 2 合并，连带 1 和 3

find(1) == find(3)?  →  是（都在 {0,1,2,3}）
find(1) == find(4)?  →  否

    1.1 为什么不用别的数据结构¶

    需求 哈希表 链表 并查集
    查"x 和 y 同集？" O(1)（存标签） O(1)（存标签） O(α) ≈ O(1)
    合并两个集合 O(n)（改所有标签） O(1)（接链表尾） O(α) ≈ O(1)
    增量加边判连通 O(n) 每次 O(1) 但要存链表 O(α) 且不存邻接表

    哈希表查同集快，但合并要改一个集合所有元素的标签 O(n)。链表合并快（接尾），但要存链表 O(n) 内存。并查集两个操作都近 O(1)，且只存 parent 数组 O(n) 内存——这是它的核心优势。

    2. 父指针表示：森林¶

    并查集用森林（forest）表示集合：每棵树是一个集合，树根是代表元。每个元素存一个 parent 指针指向父节点，根的 parent 指向自己。

    集合 {0,1,2,3} 和 {4,5}:

    树表示:          parent 数组:
       0              index: 0  1  2  3  4  5
      / \             parent:0  0  0  1  4  4
     1   2
     |
     3

    4
     \
      5

  find(x) = 沿 parent 走到根
  find(3) = 3 → 1 → 0  (根是 0)
  find(5) = 5 → 4      (根是 4)

    为什么用树？ 因为合并极快：union(x,y) 只需把一棵树的根挂到另一棵树的根下——改一个 parent 指针。

    union(3, 5):  把 4 挂到 0 下
  before:        after:
     0              0
    / \            /|\
   1   2          1 2 4
   |              |   |
   3              3   5
   (根 0)         (根 0)
   4
    \
     5
   (根 4)

    合并只需 parent[4] = 0，一个赋值。这是并查集比哈希表合并快的原因。

    2.1 朴素实现的退化¶

    如果每次 union 都把一棵树挂到另一棵树下，最坏情况会退化成链表：

    union(0,1), union(1,2), union(2,3), ..., union(n-2, n-1):

  0 ← 1 ← 2 ← 3 ← ... ← n-1   (一条链)

  find(n-1) 要走 n 步 → O(n)
  n 次 find 总 O(n²)

    树高 O(n)，find 退化成 O(n)。两个优化让树高降到近 O(1)：路径压缩和按秩合并。

    3. find 和路径压缩¶

    路径压缩（Path Compression）：find(x) 沿 parent 走到根后，把路径上所有节点直接挂到根下——下次 find 这些节点就是 O(1)。

    find(3) 前的链:        find(3) 后:
  0                     0
  |                    /|\
  1                   1 2 3   ← 路径上所有节点直接挂到根
  |                   
  2                   
  |                   
  3                   

  下次 find(3) = O(1)（parent[3] 直接是根 0）

    3.1 递归实现¶

    int dset_find(DSet *ds, int x) {
    if (ds->parent[x] != x) {
        ds->parent[x] = dset_find(ds, ds->parent[x]);  // 递归找根，回溯时压缩
    }
    return ds->parent[x];
}

    递归版最简洁：parent[x] = find(parent[x]) 一行同时做"找根"和"压缩"。递归到根后，回溯时把路径上每个节点的 parent 直接改成根。

    3.2 迭代实现（两趟）¶

    递归版在 n 很大时可能栈溢出（链长 > 栈深度）。迭代版用两趟：

    int dset_find(DSet *ds, int x) {
    // 第一趟：找根
    int root = x;
    while (ds->parent[root] != root) {
        root = ds->parent[root];
    }
    // 第二趟：路径压缩，把路径上所有节点直接挂到根
    while (ds->parent[x] != root) {
        ds->parent[x], x = root, ds->parent[x];  // 保存下一个，把当前挂到根，走到下一个
    }
    return root;
}

    第一趟沿 parent 走到根，第二趟再走一遍把每个节点直接挂到根。本 C 实现用递归版（简洁），Python demo 用迭代版（避免栈溢出）。

    3.3 路径压缩的效果¶

    路径压缩后，树变得非常扁平——大部分节点直接挂在根下。经过一次 find，后续 find 几乎都是 O(1)。但路径压缩单独用还不够：最坏情况下第一次 find 仍可能 O(n)。需要配合按秩合并保证树高始终小。

    4. union 和按秩合并¶

    按秩合并（Union by Rank）：union 时把矮树挂到高树下，避免树高增长。rank 是树高的上界（路径压缩后不精确，但够用）。

    int dset_union_sets(DSet *ds, int x, int y) {
    int rx = dset_find(ds, x);
    int ry = dset_find(ds, y);
    if (rx == ry) return 0;                    // 已在同一集合，不合并
    if (ds->rank[rx] < ds->rank[ry]) {         // 保证 rx 是 rank 大的
        int tmp = rx; rx = ry; ry = tmp;
    }
    ds->parent[ry] = rx;                       // 矮树挂到高树下
    if (ds->rank[rx] == ds->rank[ry]) {        // 等高时高树 rank +1
        ds->rank[rx]++;
    }
    ds->n_sets--;
    return 1;
}

    4.1 rank 的含义¶

    rank 是树高的上界（不是精确高度，因为路径压缩会降高但不更新 rank）。关键性质：

    • 矮树挂到高树下，树高不变
    • 等高树合并，树高 +1
    • rank 为 k 的树至少有 $2^k$ 个节点 → 树高最多 $\log_2 n$
    rank 0:  单个节点        rank 1:  两节点合并     rank 2:  两个 rank 1 合并
    x                   x                    x
                        |                   / \
                        y                  y   z
                                           |   |
                                          ...  ...

    4.2 按秩合并的效果¶

    只按秩合并（不路径压缩），树高最多 $\log_2 n$，find 是 $O(\log n)$。n=10⁶ 时树高最多 20——已经很快。但配合路径压缩后，能做到近 O(1)。

    4.3 两个优化必须一起用¶

    优化 树高 find union
    都不用 O(n) O(n) O(1)
    只路径压缩 摊还 O(α) 摊还 O(α) 摊还 O(α)
    只按秩合并 O(log n) O(log n) O(log n)
    两者都用 近 O(1) 摊还 O(α) 摊还 O(α)

    路径压缩单独用已经是摊还 O(α)，但按秩合并让常数更小、实际更快。两者一起用是标准做法。

    5. 复杂度：Ackermann 反函数 α(n) ≈ 近 O(1)¶

    两个优化一起用，find 和 union 的摊还复杂度是 $O(\alpha(n))$，其中 $\alpha(n)$ 是 Ackermann 反函数。

    5.1 Ackermann 函数¶

    Ackermann 函数 $A(m, n)$ 是一个增长比任何原始递归函数都快的函数：

    A(0, n)   = n + 1
A(m+1, 0) = A(m, 1)
A(m+1, n+1) = A(m, A(m+1, n))

A(0, n) = n+1
A(1, n) = n+2
A(2, n) = 2n+3
A(3, n) = 2^(n+3) - 3
A(4, n) = 2^2^...^2 - 3   (n+3 个 2 的幂塔)

    $A(4, 1)$ 已经是 $2^{65536} - 3$，远超宇宙原子数。

    5.2 Ackermann 反函数¶

    $\alpha(n)$ 是 $A$ 的反函数：$\alpha(n) = \min{m : A(m, m) \geq n}$。

    因为 $A$ 增长极快，$\alpha$ 增长极慢：

    $n$ $\alpha(n)$
    $n \leq 3$ 0
    $n \leq 7$ 1
    $n \leq 2^{65536}$ 4

    对任何实际数据量，$\alpha(n) \leq 4$。宇宙原子数 $\approx 10^{80} < 2^{65536}$，所以 $\alpha(10^{80}) = 4$。

    5.3 实际含义¶

    并查集的 find/union 是 $O(\alpha(n))$，对任何实际问题 $\alpha(n) \leq 4$——常数时间。所以并查集被称为"近 O(1)"。

    n 次 union + m 次 find 的总成本是 $O((n+m) \cdot \alpha(n))$，实际就是 $O(n+m)$。这是并查集的强大之处：几乎所有操作都是常数时间。

    5.4 为什么不是真的 O(1)¶

    理论上 $\alpha(n)$ 不是常数——它会随 n 增长，只是增长极慢。所以严格说是 $O(\alpha(n))$ 不是 $O(1)$。但实际中 $\alpha(n) = 4$ 对任何可想象的 n 都成立，所以工程上当作 O(1) 完全合理。

    6. C 实现逐行讲解¶

    本实现文件 10_disjoint_set/c/dset.h + dset.c。

    6.1 数据结构（dset.h）¶

    typedef struct {
    int *parent;    // 父指针数组，parent[x] 是 x 的父节点
    int *rank;      // 秩数组，rank[x] 是以 x 为根的树高上界
    size_t n;       // 元素总数
    size_t n_sets;  // 当前集合数（初始 n，每次 union 减 1）
} DSet;

    只有两个数组 parent 和 rank，内存 $O(n)$。n_sets 维护集合数，union 时减 1，O(1) 查询。

    6.2 初始化（dset_init）¶

    void dset_init(DSet *ds, size_t n) {
    ds->n = n;
    ds->n_sets = n;                          // 初始 n 个单元素集合
    ds->parent = (int *)malloc(n * sizeof(int));
    ds->rank = (int *)calloc(n, sizeof(int));  // rank 初始全 0
    for (size_t i = 0; i < n; i++) {
        ds->parent[i] = (int)i;              // 每个元素自成一集，parent 指向自己
    }
}

    初始每个元素是一个单节点树，parent[i] = i（根指向自己），rank 全 0。

    6.3 find 带路径压缩（dset_find）¶

    int dset_find(DSet *ds, int x) {
    if (ds->parent[x] != x) {
        ds->parent[x] = dset_find(ds, ds->parent[x]);  // 递归找根，回溯时压缩
    }
    return ds->parent[x];
}

    parent[x] != x 说明 x 不是根，递归找根。回溯时 parent[x] = root 把 x 直接挂到根下。一行同时做"找根"和"路径压缩"。

    6.4 union 按秩合并（dset_union_sets）¶

    int dset_union_sets(DSet *ds, int x, int y) {
    int rx = dset_find(ds, x);               // 找 x 的根
    int ry = dset_find(ds, y);               // 找 y 的根
    if (rx == ry) return 0;                  // 已同集，不合并，返回 0
    if (ds->rank[rx] < ds->rank[ry]) {       // 保证 rx 是 rank 大的
        int tmp = rx; rx = ry; ry = tmp;
    }
    ds->parent[ry] = rx;                     // 矮树（ry）挂到高树（rx）下
    if (ds->rank[rx] == ds->rank[ry]) {      // 等高时高树 rank +1
        ds->rank[rx]++;
    }
    ds->n_sets--;                            // 集合数减 1
    return 1;                                // 合并成功，返回 1
}

    关键三步： 1. find 两边根（同时路径压缩） 2. 矮树挂高树下（保证树高不增） 3. 等高时 rank+1（树高增 1）

    返回值：1 表示合并了，0 表示已同集。n_sets 维护集合数。

    6.5 connected 和 count_sets¶

    int dset_connected(DSet *ds, int x, int y) {
    return dset_find(ds, x) == dset_find(ds, y);  // 同根即连通
}

size_t dset_count_sets(DSet *ds) {
    return ds->n_sets;                       // O(1) 查询，不用数根
}

    connected 两次 find 比根，$O(\alpha)$。count_sets 直接返回维护的 n_sets，O(1)。

    7. 与 BFS/DFS 判连通对比¶

    判"两个顶点是否连通"有两种做法：

    方法 数据结构 判连通 加边 内存 增量加边
    BFS/DFS 邻接表 O(V+E) O(1) O(V+E) O(V+E) 重建
    并查集 parent[] O(α) O(α) O(V) O(α)

    7.1 一次性判连通¶

    给定一个图，判"u 和 v 是否连通"：

    • BFS/DFS：从 u 出发遍历整个连通分量，看能否到 v。O(V+E) 时间，O(V+E) 内存（存邻接表）
    • 并查集：对所有边 union 一遍，然后 find(u) == find(v)。O(E·α) 时间，O(V) 内存

    并查集时间多一个 α 因子（但 α≈4），内存省 O(E)（不存邻接表）。

    7.2 增量加边判连通¶

    核心差异：如果图在不断加边，每次加边后要判连通：

    • BFS/DFS：每次加边后，连通分量可能变，要重新 BFS O(V+E)。加 k 条边总 O(k·(V+E))
    • 并查集：每次加边就 union O(α)，判连通就 find O(α)。加 k 条边总 O(k·α)

    这是层次聚类的核心场景：逐步降低距离阈值，每次新边出现，两个簇合并。并查集每次 O(α)，BFS 每次重建 O(V+E)。

    7.3 具体数字¶

    n=10000 点，E≈2000000 边，10 次阈值更新：

    方法 10 次更新总成本 实测
    并查集 10 × ΔE × α ≈ 10 × 200000 × 4 = 8M ~6.5 秒
    BFS 重建 10 × (V+E) = 10 × 2010000 = 20M ~24 秒

    实测并查集快 3.7x（纯 Python 开销拉低了理论优势，C 实现差距更大）。内存上并查集 O(V) = 80KB，BFS O(V+E) = 30MB，省 400x。

    7.4 什么时候用 BFS/DFS¶

    并查集只能判"是否连通"，不能：

    • 找最短路径（BFS 的本职工作）
    • 遍历连通分量里的所有节点（BFS/DFS 可以，并查集要扫全图数根）
    • 处理带权图的最短路（Dijkstra/Bellman-Ford）

    所以并查集用于只需判连通/维护连通分量的场景。需要路径信息时用 BFS/DFS。

    8. 复杂度汇总¶

    操作 时间 空间
    init(n) O(n) O(n)
    find(x) O(α(n)) 摊还 O(1)
    union(x,y) O(α(n)) 摊还 O(1)
    connected(x,y) O(α(n)) 摊还 O(1)
    count_sets() O(1) O(1)
    n 次 union + m 次 find O((n+m)·α(n)) O(n)

    $\alpha(n) \leq 4$ 对任何实际 n，所以工程上所有操作都是 O(1)。这是并查集被称为"最接近魔法的数据结构"的原因。

    9. 总结¶

    并查集的三个关键思想：

    1. 父指针表示：用森林表示集合，合并只需改一个指针
    2. 路径压缩：find 时把路径压平，后续 find 近 O(1)
    3. 按秩合并：矮树挂高树下，树高最多 O(log n)

    三者配合，得到 $O(\alpha(n))$ 摊还复杂度——对任何实际数据量都是常数时间。内存只 O(V)（不存邻接表），增量加边 O(α)（不重建）。这让并查集成为层次聚类、Kruskal MST、连通分量维护的首选数据结构。

    AI 应用¶

    并查集的 AI 应用：层次聚类 HAC 的连通分量维护¶

    本文档讲清「并查集在 AI 里干什么」。原理见 principle.md。核心应用：层次聚类（Hierarchical Agglomerative Clustering, HAC） 的连通分量维护。HAC 合并频繁，并查集的近 O(1) union 让增量维护极快，而 BFS 每次要重建 O(V+E)——这是并查集在 AI 里的杀手级应用。

    1. 聚类在 AI 里的应用¶

    聚类（Clustering）是无监督学习的核心任务：给定一堆没有标签的数据点，按相似性自动分簇。它在 AI 里无处不在：

    应用 场景 聚类作用
    客户分群 电商/广告 按行为特征分客户群，精准营销
    图像分割 计算机视觉 按像素相似性分区域，提取物体
    文档主题 NLP/搜索 按词频分文档簇，自动发现主题
    异常检测 风控/运维 远离所有簇的点是异常
    基因表达 生物信息 按表达模式分基因簇，找功能模块
    向量检索 RAG/推荐 聚类加速近似最近邻搜索

    聚类算法分三大类：

    1. 划分式（K-Means）：指定 K 个簇，迭代分配
    2. 密度式（DBSCAN）：高密度区域连成簇
    3. 层次式（HAC）：逐步合并/分裂，产生聚类树

    层次聚类的独特价值是产生树状图（dendrogram）——一次运行得到所有粒度的聚类，用户按需切树。这让 HAC 在探索性分析中不可替代。

    2. 层次聚类 HAC 原理¶

    层次聚类（Hierarchical Agglomerative Clustering）从每个点自成一簇开始，逐步合并最相似的两个簇，直到所有点合为一簇（或达到目标簇数）。

    2.1 算法骨架¶

    HAC(点集 P, 距离函数 d):
  clusters = {{p} for p in P}          # 初始每个点一簇
  while len(clusters) > 1:
    (A, B) = argmin d(Ci, Cj)          # 找最近的两个簇
    clusters.remove(A); clusters.remove(B)
    clusters.add(A ∪ B)                # 合并
  return 合并历史（树状图）

    每步找最近的两个簇合并。簇间距离的定义决定变体：

    变体 簇间距离 特点
    单链接（Single Linkage） $\min_{a \in A, b \in B} d(a,b)$ 最近的两点距离
    全链接（Complete Linkage） $\max_{a \in A, b \in B} d(a,b)$ 最远的两点距离
    平均链接（Average Linkage） $\text{mean}_{a \in A, b \in B} d(a,b)$ 所有点对平均
    Ward 合并后方差增量 最小化簇内方差

    2.2 单链接 HAC 与连通分量¶

    单链接层次聚类有一个优美性质：它等价于按距离阈值连边后的连通分量。

    单链接 HAC 在阈值 t 时的聚类 = 图 G(t) 的连通分量

其中 G(t) 的边集 = {(i,j) : d(p_i, p_j) <= t}

    直觉：单链接用"最近两点距离"定义簇间距离，所以两个簇合并当且仅当它们之间有一条边距离 ≤ t。这正好是图 G(t) 的连通分量。

    点集:  ●  ●    ●●●     ●●
       1  2    345      67

阈值 t=1.0 时的图 G(1.0):
  1   2    3-4-5    6-7
  (孤立)(连通分量)(连通分量)

聚类: {1}, {2}, {3,4,5}, {6,7}  = 4 个簇

阈值 t=2.0 时:
  1-2    3-4-5    6-7
  (连通分量)(连通分量)(连通分量)

聚类: {1,2}, {3,4,5}, {6,7}  = 3 个簇

    关键洞察：单链接 HAC 就是逐步增大阈值，每次新边出现，两个连通分量合并。这正是并查集的增量 union 场景！

    2.3 HAC 的实现路线¶

    路线 数据结构 时间复杂度 适用
    朴素 距离矩阵 + 簇列表 $O(n^3)$ n < 1000
    优先队列 堆 + 簇间距离 $O(n^2 \log n)$ n < 10000
    单链接 + 并查集 边排序 + 并查集 $O(n^2 + E \log E)$ 单链接专用，n < 50000
    scipy hierarchy 优化 C 实现 $O(n^2)$ 生产级

    单链接 HAC 用并查集是最快的：把所有点对距离排序，按距离从小到大加入边，每次 union 两个簇。这本质是 Kruskal 算法在聚类上的应用。

    3. 并查集维护连通分量¶

    3.1 单链接 HAC 的并查集实现¶

    def hac_single_linkage(points, thresholds):
    n = len(points)
    ds = DisjointSet(n)                           # 初始每个点一集
    edges = find_all_edges_sorted(points)          # 所有点对按距离排序
    history = []
    next_edge = 0
    for t in thresholds:                          # 逐步增大阈值
        while next_edge < len(edges) and edges[next_edge].dist <= t:
            u, v = edges[next_edge].u, edges[next_edge].v
            ds.union(u, v)                        # 新边出现，合并两个簇
            next_edge += 1
        history.append(ds.n_sets)                 # 当前簇数 = 连通分量数
    return history

    核心：边按距离排序，逐步加入，每次 union 两个簇。并查集维护"哪些点在同一簇"。

    3.2 为什么并查集是最佳选择¶

    HAC 的核心操作是合并——每次把两个簇合体。并查集的 union 就是为此设计：

    操作 并查集 BFS 重建 优势
    合并两个簇 union O(α) ≈ O(1) 重建邻接表 + BFS O(V+E) 快 V+E 倍
    查簇数 n_sets O(1) 数连通分量 O(V+E) 快 V+E 倍
    查两点同簇 find O(α) BFS O(V+E) 快 V+E 倍
    内存 parent[] O(V) 邻接表 O(V+E) 省 E 倍

    HAC 合并 n-1 次（从 n 个单点簇到 1 个全簇）。并查集总成本 $O(n \cdot \alpha)$，BFS 总成本 $O(n \cdot (V+E))$。差距巨大。

    3.3 增量合并的场景¶

    HAC 不是一次性算所有阈值，而是逐步增大阈值，每次只新增一些边：

    阈值序列: t=0.3, 0.5, 0.7, 1.0, 1.5, 2.0

t=0.3:  加入 100 条边    →  并查集 union 100 次 O(100·α)
t=0.5:  新增 500 条边    →  并查集 union 500 次 O(500·α)  （只处理新增！）
t=0.7:  新增 2000 条边   →  并查集 union 2000 次 O(2000·α)
...

并查集总成本 = O(E · α)  （每条边只 union 一次）

BFS 每个阈值都要重建:
t=0.3:  重建 O(V + 100)
t=0.5:  重建 O(V + 600)    （重新建整个邻接表）
t=0.7:  重建 O(V + 2600)
...

BFS 总成本 = O(k · (V + E))  （k 个阈值，每次重建）

    并查集的增量优势：每条边只处理一次，总 O(E·α)。BFS 每个阈值重建，总 O(k·(V+E))。k=10 时并查集快 10 倍。

    4. demo 结果解读¶

    本 demo（10_disjoint_set/python/demo.py）对比并查集 vs BFS 在层次聚类中的性能。

    4.1 实验设置¶

    • 生成 n 个 2D 点，分布在多个高斯团里
    • 用 cKDTree 高效找所有距离 ≤ 阈值的边
    • 两种方法找连通分量：
    • cluster_dset：并查集流式 union，不存邻接表
    • cluster_bfs：建邻接表 + BFS
    • 增量场景：10 个阈值批次，逐步增大阈值

    4.2 一次性计算结果¶

    n 边数 平均度 并查集时间 BFS 时间 内存比 (BFS/并查集)
    1000 56k 113 87 ms 66 ms 57x
    5000 571k 228 841 ms 728 ms 115x
    10000 1.94M 389 2859 ms 2407 ms 195x
    50000 37.8M 1512 57125 ms 51247 ms 756x

    解读： - 时间：纯 Python 并查集略慢于 BFS（函数调用开销 + 稠密图 BFS 的 list 迭代效率高）。C 实现并查集会快很多（无函数调用开销） - 内存：并查集 O(V) vs BFS O(V+E)，省 57x~756x。n=50000 时 BFS 邻接表占 590MB，并查集只 781KB——这是并查集的决定性优势

    4.3 增量合并结果（HAC 核心场景）¶

    n=10000，10 个阈值批次（0.3 → 2.0）：

    方法 总时间 说明
    并查集增量 6459 ms 每个阈值只 union 新增边
    BFS 重建 23748 ms 每个阈值重建邻接表 + BFS
    加速比 3.68x

    各阈值下簇数变化（两种方法一致）：

    阈值:   0.30  0.50  0.70  0.90  1.00  1.10  1.20  1.30  1.50  2.00
簇数:    13    2     1     1     1     1     1     1     1     1

    阈值 0.3 时 13 个簇（同簇点已连通，异簇未连），0.5 时 2 个簇（大部分合并），0.7 时全合为 1 簇。

    不同点数下增量合并的加速比：

    n 并查集 BFS 加速比
    2000 294 ms 1109 ms 3.77x
    5000 1649 ms 5897 ms 3.58x
    10000 6323 ms 23679 ms 3.75x
    20000 25725 ms 97549 ms 3.79x

    加速比稳定在 3.7x 左右，因为并查集总成本 O(E·α)，BFS 总成本 O(k·(V+E))，比值约 k/α ≈ 10/4 = 2.5（实际 3.7，因为 BFS 重建还有邻接表分配开销）。

    4.4 为什么纯 Python 并查集一次性计算略慢¶

    纯 Python 的并查集每条边调用 union（2 次 find + 比较 + 路径压缩），函数调用开销大。BFS 建邻接表用 list.append（C 实现，快），BFS 遍历用 for nb in adj[node]（list 迭代，C 实现）。

    C 实现并查集没有这个问题——本 C 测试中 200000 次 union + 200000 次 connected 只用 14ms。生产级并查集（C/C++）一次性计算也快于 BFS。

    4.5 内存优势是决定性的¶

    即使时间相近，并查集的内存优势巨大：

    n=50000, E=37.8M:
  并查集: parent[] + rank[] = 50000 * 8 * 2 = 800 KB
  BFS:    邻接表 = 50000 * 8 + 37.8M * 2 * 8 = 590 MB
  比值:   756x

    对于大规模数据，BFS 的 O(V+E) 内存可能放不下，而并查集 O(V) 总能放下。这是并查集在大规模层次聚类中的关键优势。

    5. 生产级实现：scipy hierarchy¶

    生产环境不用手写并查集，用 scipy.cluster.hierarchy：

    from scipy.cluster.hierarchy import linkage, fcluster
from scipy.spatial.distance import pdist

# 1. 算所有点对距离（ condensed 形式）
distances = pdist(points)                    # O(n²) 内存

# 2. 层次聚类（C 实现，内部用并查集）
Z = linkage(distances, method='single')      # O(n² log n)

# 3. 按阈值切簇
labels = fcluster(Z, t=1.0, criterion='distance')  # O(n)

    5.1 scipy hierarchy 的优化¶

    scipy 的 linkage 用优化的 C 实现，内部核心就是并查集：

    1. 单链接：用 Kruskal 思路 + 并查集，O(n²) 排序边 + O(n·α) 合并
    2. 全链接/平均链接/Ward：用优先队列 + 距离更新，O(n² log n)
    3. fcluster：在合并历史上二分切簇，O(n)

    5.2 什么时候手写并查集¶

    场景 选择 原因
    标准层次聚类 scipy hierarchy 优化 C 实现，接口完整
    流式数据（边一条条来） 手写并查集 scipy 不支持增量
    自定义合并逻辑 手写并查集 灵活控制 union 时机
    超大规模（内存不够） 手写并查集 O(V) 内存，scipy 要 O(n²) 存距离矩阵
    教学/理解原理 手写并查集 理解近 O(1) 的来源

    scipy 的 pdist 要存 $O(n^2)$ 距离矩阵，n=50000 时 10GB——放不下。这时用 cKDTree 找边 + 手写并查集，只 O(V+E) 内存，能处理更大规模。

    5.3 HDBSCAN：层次聚类的现代升级¶

    HDBSCAN（Hierarchical DBSCAN）是层次聚类 + 密度聚类的结合，是当前最流行的聚类算法之一：

    from hdbscan import HDBSCAN
clusterer = HDBSCAN(min_cluster_size=5)
labels = clusterer.fit_predict(points)

    HDBSCAN 内部也用并查集维护连通分量——构建互达距离的 MST 时用 Kruskal + 并查集。这再次说明并查集在聚类算法中的核心地位。

    6. 并查集在其他 AI 算法中的应用¶

    6.1 Kruskal 最小生成树¶

    Kruskal 算法找 MST 时，按边权排序，依次加入不构成环的边。"不构成环"就是"两端不在同一连通分量"——并查集判连通：

    def kruskal(n, edges):
    ds = DisjointSet(n)
    edges.sort(key=lambda e: e.weight)
    mst = []
    for e in edges:
        if not ds.connected(e.u, e.v):    # O(α) 判环
            ds.union(e.u, e.v)            # O(α) 合并
            mst.append(e)
            if len(mst) == n - 1: break
    return mst

    总成本 $O(E \log E + E \cdot \alpha)$。并查集让"判环"从 BFS 的 O(V+E) 降到 O(α)。

    6.2 图神经网络的消息聚合¶

    GNN 在大图上做消息传递时，常用图分区把大图切成小块。分区后要维护"哪些节点在同一块"——并查集。增量切分（加边改变分区）时并查集的 O(α) union 优势明显。

    6.3 并行图计算¶

    图计算的并行框架（GraphX、Giraph）用并查集做跨分区连通分量合并：每个分区独立算连通分量，然后跨分区合并时用并查集 union 不同分区的代表元。并查集的 O(α) 让合并阶段极快。

    6.4 半监督标签传播¶

    标签传播算法中，已知标签的点通过图结构把标签扩散到未知点。维护"哪些点已确定标签"可以用并查集——合并已确定和未确定的点集，O(α) 每次。

    7. 总结¶

    并查集在 AI 里的核心应用是层次聚类的连通分量维护：

    1. 单链接 HAC = 按距离阈值连边的连通分量：并查集天然适合
    2. 合并频繁是 HAC 的本质：并查集 union O(α) ≈ O(1)，BFS 重建 O(V+E)
    3. 增量加边只 union 新边：总 O(E·α)，BFS 每次重建 O(k·(V+E))
    4. 内存 O(V) 不存邻接表：比 BFS 省 E 倍，大规模数据关键

    demo 实测：增量合并并查集快 3.7x，内存省 756x。生产级用 scipy hierarchy（内部也是并查集），超大规模用手写并查集 + cKDTree（省 O(n²) 距离矩阵内存）。

    并查集的近 O(1) 合并是层次聚类、Kruskal MST、连通分量维护的首选——这就是"路径压缩 + 按秩合并"在 AI 里的价值。
